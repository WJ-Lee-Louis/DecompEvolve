원본 Train 진단 → nano 모형 제안 → M과 M′ 검증 → 문장 생성 → 다음 배치
request ← (원문 조건, 풀이 인용, 불일치 이유, 점검 지침, skill)
for attempt in [최초 제안, 검증 사유를 전달한 수정]:

의사코드에서 스키마 오류는 solver 호출 전에 기각한다. 단위 환산에는 표시 단위와 기준 단위가, 목적식 변경에는 매출·원가가 각각 필요하다. 실제 생산 계획까지 달라져야 하는 유형에서는 두 최적해 집합의 교집합이 비었는지도 검사한다. 정상 모형에서 검증한 필드로 문장을 렌더링해 자유 서술 과정에서 부등호나 단위가 달라질 여지를 줄인다.

검증 사례. 일반·인증 조달량 x,y에 대해 min 2x+5y, x+y≥12, 3y≥x+y, 0≤x,y≤12이면 최적값은 36이다. 비중 조건만 제거하면 24다. 이는 목표 오류가 점수에 영향을 줄 수 있음을 입증한다. 실제 오답의 원인을 특정하려면 공개 풀이의 근거가 별도로 필요하다.

④에서는 유한 변수 경계와 목적 방향을 명시해 최소화·최대화, 양방향 부등식, 두 변수 모두 연속 또는 모두 정수인 경우를 처리한다. 요청·시도·기각 사유·수학 모형·정답 인증·출제 토큰을 기록하고 재개 시 캐시를 복원한다. 변수 순서·제약 순서·제약식의 양의 정수배를 정규화한 수학 모형 지문으로 중복을 거른다. 계수가 달라진 유사 문제의 의미적 중복률은 별도 분석 대상이다.

한 반복의 실행 순서

최적화 변수는 후보 사전의 instructions 문자열 하나입니다. 기본 프롬프트에서 풀이 지시를 분리해 진화시키고, 실제 요청에는 고정된 최종 답안 형식을 붙입니다. 풀이·진단·변이는 모두 도구 없는 gpt-5.4-nano 호출입니다. 정답 비교, 부모 추출, 자식 수락, 수학 검증은 프로그램이 맡습니다. ④에서는 출제 nano가 새 모형을 제안합니다.

부모·배치 선택 → 풀이·채점 → 오답 진단 → 지침 변이 → 동일 배치 비교 → 전체 검증
P ← {seed};  V[seed] ← evaluate(seed, validation[20])
for i = 0, 1, … while budget_and_time_allow:
    p ← sample_instance_frontier(V)
    B ← curriculum(i, previous_diagnoses, previous_parent_scores)
    R, s ← solve_and_grade(p, B)             # 공개 응답과 이진 점수 3개
    if sum(s) == 3: continue
    D ← diagnose_failed_parent_records(R)    # 결과를 즉시 기록
    q ← reflect(p, R, D)                    # 새 instructions 제안
    if no usable proposal: continue
    _, t ← solve_and_grade(q, B)
    if sum(t) ≤ sum(s): continue
    V[q] ← evaluate(q, validation[20])
    P.add(q); parent[q] ← p
return first_argmax(mean(V[p]) for p in P)

부모와 자식은 같은 문제 ID로 각각 새 응답을 생성합니다. 따라서 1/3 → 2/3이면 수락하며, 이전에 맞힌 문항 하나를 잃고 다른 두 문항을 얻어도 통과합니다. 2/3 → 2/3은 기각합니다. 수락 후 검증 평균이 부모보다 낮아도 계보에는 등록됩니다. use_merge=False이므로 등록된 자식의 부모는 하나입니다.

최종 시험은 이 루프 밖에서 확정된 지침으로 원본 30문항을 풉니다. 검증 20문항은 탐색에 반복 사용되며, 진단과 변이에 전달되는 사례는 훈련 배치에서만 나옵니다.

부모를 뽑는 규칙과 최종 지침을 고르는 규칙

후보 p의 검증 문항 j 점수를 V[p,j] ∈ {0,1}이라 합시다. GEPA의 frontier_type="instance"는 각 열의 최고 점수 후보 집합 Fⱼ를 유지합니다. 공동 1위는 모두 들어가며, 아직 어느 후보도 못 푼 문항에서는 0점도 공동 최고입니다.

  1. 중복 대표 제거. 문항별 최고 집합에 등장하는 후보를 검증 평균 오름차순으로 훑습니다. 후보 p가 속한 모든 Fⱼ에 다른 생존 후보가 하나 이상 있으면 p를 이번 추첨에서 제거하고 다시 훑습니다. 문항마다 다른 후보가 대신해도 됩니다. 이 연산은 추첨용 집합에만 적용되므로 원래 후보와 계보는 남습니다.
  2. 빈도 비례 추첨. 제거 후 남은 집합을 F′ⱼ라 하면, 후보 p가 등장하는 집합 수가 가중치입니다. 함께 최고인 문항에서도 각 후보가 한 표씩 얻습니다.
w(p) = Σⱼ 𝟙[p ∈ F′ⱼ]　 ·　 Pr(parent = p) = w(p) / Σᵣ w(r)

예를 들어 검증 4문항에서 A=(1,1,1,0), B=(0,0,1,1), C=(1,0,0,0)라면 C의 유일한 최고 문항은 A가 이미 대표합니다. C를 제거한 뒤 A와 B의 가중치는 3과 2여서 부모 선택 확률은 각각 60%, 40%입니다. 반면 최종 지침은 원본 검증 전체의 평균 점수가 가장 높은 A입니다. 최종 평균 동률은 먼저 등록된 후보가 이깁니다.

코드 대응 · GEPA의 ParetoCandidateSelector → remove_dominated_programs → select_program_candidate_from_pareto_front. 최종 선택은 GEPAResult.best_idx.

practice_skill이 해당 단계에 등록된 실수와 일치할 때만 합성 자격을 얻습니다. 예컨대 부등호 방향 오류도 constraints 피드백에는 쓸 수 있지만 현재 합성기는 비례 제약 누락만 구현합니다. 진단 JSON은 기존 피드백에 덧붙이고, 변이 LLM이 재사용할 점검 지침을 제안합니다. 진단 문구를 자식 지침에 강제로 삽입하지 않으므로 실제 반영 여부는 생성된 지침에서 확인해야 합니다.

합성 문항을 배치에 넣는 스케줄러

기본 배치는 원본 34문항을 Easy 16, Medium 14, Hard 4의 세 덱으로 나누어 구성합니다. 각 덱 크기 n에 대해 cycle, offset = divmod(i, n)을 구하고 seed:level:cycle로 섞은 덱의 offset 위치를 뽑습니다. 기본 슬롯 순서는 [Easy, Medium, Hard]입니다.

  1. 대상 집계. 누적 진단에서 원본 ID가 양수이고 단계와 실수 코드가 일치하는 기록만 집계합니다. 키는 (원본 ID, 단계)입니다. 합성 오답은 변이 피드백에는 쓰이지만 합성을 재귀적으로 유발하지 않습니다.
  2. 수준 계산. 키별 첫 수준은 2입니다. 이전 합성 문항이 있으면 그 문항을 푼 부모의 정답 여부로 직전 수준에 +1 또는 −1을 적용합니다. 점수가 아직 없거나 다음 수준이 1~3 밖이거나 이미 세 문항을 생성했으면 이 키는 건너뜁니다.
  3. 우선순위. (기생성 수, −진단 빈도, 원본 ID, 단계, 수준)을 사전식 오름차순 정렬합니다. 아직 덜 연습한 대상이 먼저이고, 같은 횟수라면 반복 진단된 대상이 먼저입니다. 이력은 후보 계보 전체가 공유하므로 다른 부모가 낸 정답도 다음 수준에 영향을 줍니다.
  4. 한 자리 교체. 우선순위가 가장 높은 대상으로 nano에 출제를 의뢰해 검증을 통과하고 기존 합성 문장과 정확히 같지 않은 첫 문제를 채택합니다. 합성 ID는 −1, −2, … 순서입니다. 기본 배치의 i % 3 슬롯을 교체하며 교체 대상 원본이 그 반복에서 뒤로 이월되지는 않습니다. 수정까지 실패하면 원본 세 문항을 사용합니다.
시간 순서가 중요합니다. 반복 i의 배치를 먼저 고르고 나서 부모 오답을 진단하므로, 새 진단은 가장 빨라도 i+1의 합성에 쓰입니다. 완벽 배치가 계속되고 과거에 쌓인 적격 진단도 없으면, 합성기가 스스로 어려운 문제를 추가하는 경로는 없습니다.

--diagnosis-only에서는 동일한 오류 진단과 변이를 적용하면서 합성 슬롯 교체를 끕니다. 원본 GEPA와 이 모드를 비교하면 진단의 기여를, 이 모드와 전체 방법을 비교하면 문제 합성 및 배치 교체의 결합 효과를 볼 수 있습니다.

nano가 제안한 모형과 오류 모형의 검증

출제 nano는 진단 원문과 오류 근거를 읽고 두 변수의 이름·상한·도메인, 목적 방향·계수, 자원·비례·시간 조건을 제안합니다. solver는 정상 모형과 아래의 변환을 적용한 오류 모형을 풉니다.

실수 코드정상 모형에서 바꾸는 연산
hours_minutes_conversion분 기준 생산시간 계수를 유지하면서 분으로 환산한 자원 한도를 원래 시간 숫자로 바꿉니다.
integrality_relaxation정수 생산량 제약을 풀어 연속 LP로 풉니다.
gross_vs_net_profit같은 가능 영역에서 목적식 계수를 순이익에서 판매가격으로 바꾸고 그 매출 최적값을 사용합니다. 두 목적식에 공통인 최적 계획이 있으면 기각합니다.
proportional_link연결 제약 x ≤ r·y 한 줄만 제거합니다.
missed_mixed_optimumx=0 또는 y=0으로 각각 제한한 두 최적값 중 큰 값을 사용합니다.

연속 모형은 좌표축까지 포함한 경계선 쌍의 교점을 유리수로 구하고 모든 부등식을 만족하는 점에서 목적값을 최대화합니다. 정수 모형은 모형에 명시된 x,y의 유한 범위에서 정수점을 전수 조사합니다. 정상 최적값 z가 양의 정수이고 오개념 모형의 최적값 z′가 z와 다를 때 채택합니다. 정수 조건은 목적값에 적용되므로 연속 LP의 최적 생산량은 분수여도 됩니다. 슬롯당 첫 제안과 수정 1회까지 허용합니다.

무엇을 보증하는가? 원래 모형을 풀어 얻은 z를 참조 답으로 저장합니다. 목표 실수를 적용해 얻은 z′는 그 실수를 점수로 식별할 수 있는지 판정하는 데 씁니다. 두 계산 모두 출제 단계에서 수행하며 풀이 LLM에는 문제 문장과 지침만 전달합니다.

생성 모형의 계수와 단위를 검증한 뒤 같은 데이터로 문제 문장을 만듭니다. 풀이 LLM에는 정답·인증서·오류 변환 정보를 보내지 않습니다.

한 번의 후보 수락 예시

검증된 합성 문항이 포함되어 원본·합성·원본 순서의 배치가 구성됐다고 가정합니다. 부모 점수 [1,0,1], 자식 점수 [1,1,1]이면 자식은 원본 검증 20문항에 진입합니다. 같은 진단의 다음 출제 수준은 부모의 합성 문항 점수 0에 따라 한 단계 낮아집니다. 실제 성능 수치는 실행 로그에 기록합니다.

호출 예산, 중단, 재개

사건풀이 호출추가 LLM 호출
초기화시드 검증 20회없음
부모 3/33회없음
자식 제안·기각부모 3 + 자식 3 = 6회적격 오답별 진단 최대 3회, 지침 변이 1회
자식 수락3 + 3 + 20 = 26회동일
최종 시험30회, 최적화 예산 외부없음

Train+Validation 풀이 예산 기본값은 1,200회입니다. 반복 시작 시 기록된 호출 수 + 26 > 예산이면 종료합니다. 따라서 실제 사용량은 1,200 미만일 수 있고 CLI의 최소 허용 예산은 20+26=46입니다. 진단·변이 호출은 별도입니다. 새 ④는 출제와 수정 호출도 별도 역할로 집계합니다. 위 표의 추가 LLM 호출 수는 기존 변이 경로 기준이며 ④의 합성 슬롯당 출제 요청은 최대 2회입니다. 변이가 한도에 걸려 유효한 제안이 없으면 자식 풀이도 생략합니다.

기본 병렬도 4, 풀이 제한 900초·65,536 출력 토큰, 진단·변이 각각 60초·8,192 토큰, 출제는 시도당 180초·12,288 출력 토큰입니다. 실행 기한을 전달하면 시드 검증에 5×900초, 전체 DecompEvolve 한 반복에 (1+1+5)×900 + (3+1)×60 + 2×180 = 6,900초를 확보할 수 있는지 검사합니다. 시간 여유가 부족하면 일시정지하고, 풀이 예산이 부족하면 탐색을 종료해 최종 지침을 확정합니다.

재개 시 모델·프롬프트·분할·예산·코드 해시 등을 포함한 manifest.json 일치를 확인합니다. GEPA 상태가 있으면 시드 검증을 생략하고, 없으면 기록된 시드 평가 중 API 오류 외의 항목을 재사용합니다. 커리큘럼은 합성 이력으로 로더를 복원하고 이미 정한 반복의 원본 전용 또는 합성 슬롯을 재사용합니다. 중단된 반복의 모델 요청은 다시 발생할 수 있으며, 이미 기록된 풀이도 예산에 포함됩니다.

실행 기록에서 대조할 값

train_batches.jsonl의 indices와 scores는 부모의 3/3 건너뛰기와 난이도 결정에, diagnoses.jsonl의 index와 diagnosis는 합성 자격 확인에 씁니다. synthetic.jsonl은 원본 ID·단계·수준·음수 ID·부등식·최적해·오개념 값을 잇습니다. reflections.jsonl의 purpose와 usage로 진단·변이 비용을 분리하고, optimization.json의 parents·val_subscores·val_aggregate_scores로 계보와 검증 결과를 재구성합니다.
